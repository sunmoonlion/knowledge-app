# Dev → Prod Celery Worker 转换流程

`tpl-app` 现在直接包含两个 Celery Worker 模板实例，不再通过单独的 scaffold 临时生成。

## 自动生成

```bash
cd tpl-app
./init.sh <app-name>
```

初始化完成后会把模板目录重命名为：

```text
celeryworker-<app-name>-web-backend/
celeryworker-<app-name>-admin-backend/
```

## 生成后检查

- Worker Deployment 默认使用 backend 镜像，保证任务代码与 backend 保持一致。
- Worker Pod 注入 backend 的 ConfigMap/Secret，因此数据库等业务配置不另建一套。
- Worker 自身 Secret 中的 `CELERY_BROKER_URL` 需要按实际 RabbitMQ 用户、密码、Service、vhost 调整。
- RabbitMQ 队列由 Worker initContainer 通过 `kombu` 声明。
