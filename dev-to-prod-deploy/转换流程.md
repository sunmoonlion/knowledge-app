# Dev → Prod Worker 转换流程

`tpl-app` 现在直接包含两个 worker 模板实例，不再通过单独的 scaffold 临时生成。

## 自动生成

```bash
cd tpl-app
./init.sh <app-name>
```

初始化完成后会把模板目录重命名为：

```text
nodebullworker-<app-name>-web-backend/
celeryworker-<app-name>-admin-backend/
```

## 生成后检查

- Worker Deployment 默认使用 backend 镜像，保证任务代码与 backend 保持一致。
- Worker Pod 注入 backend 的 ConfigMap/Secret，因此数据库等业务配置不另建一套。
- RabbitMQ vhost、用户、权限和队列由 `messaging-platform/rabbitmq` 的 app definitions 统一创建。
- Worker 自身 Secret 中的 `CELERY_BROKER_URL` 默认指向 `rabbitmq-sunmoonai.messaging-platform-dev.svc.cluster.local` 和受限 worker 用户。
- `web-backend` 当前是 Node.js 技术栈，不能直接用 Python Celery 启动；生产启用用户端异步 worker 前，需要改为 Node.js MQ worker 或确认镜像内已包含 Python Celery 运行时。
